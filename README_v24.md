# オウダン v24:補完を「売れる商品」に集中+1日4回の自動取得+ランキング下位が増え続けない

## 変わること
1. **補完(他サイトで同じ商品を探す)の対象を絞りました**
   - 対象:有名ブランドの商品/どこかのサイトのランキングで **300位以内**/まとめ(/c)に入っている商品
   - 301〜1000位だけの商品は、そのサイトの価格とランキングは記録しますが、他サイトでは探しません
2. **補完だけを行う回を1日2回追加**(午前11時ごろ・午後11時ごろ、各25分)
   - 1日の補完の目安:楽天 約780件→約2,400件/Yahoo! 約320件→約4,000件/Amazon 約540件→約2,300件
3. **Yahoo!の間隔を2.1秒→1.1秒**(公式の「1秒に1回」は守ったまま)
4. **ランキング下位が増え続けないように**、毎日4:30の自動削除を3段階にしました
   - ランキング圏外になった下位の商品(ブランドでない・1サイトだけ・300位以内に入ったことがない)→ 圏外になって3日で削除
   - 300位以内に入ったことがある/2サイト以上で比べられる/有名ブランド → 45日見かけなければ削除(今までどおり)
   - まとめに入っている商品 → 消さない
   - 安全装置:商品が15万件を超えたら、価値の低い古いものから削除

## 費用(GitHub Actions)
- 1日約103分+準備の時間 → 月約3,400分。無料の2,000分を超える約1,400分が有料($0.006/分)で **月約$8〜9**
- 先に GitHub の Settings → Billing and licensing でカード登録と予算(Budgets)を設定してください。予算を $10 にすると、それ以上は請求されません(超えたらその月の残りは自動取得が止まります)
- カードを登録しない場合は、月の2,000分で止まります(月の後半に自動取得が止まる)

## Amazonの回数
- 自動取得は1日 最大3,600回(午前900・午後900・補完2回×900)。上限は1日8,640回(Xツールと合算)
- Xツールの `track`(価格の取り直し)は **1日2回まで** にしてください(1回最大1,200回)

## 手順(SQL → アップロード)
1. Supabase の SQL Editor に `sql/v24-fill-focus.sql` を全部貼って Run(最後に「商品数・補完の対象・補完待ち」が出ればOK)
2. GitHub に **collector フォルダ** と **sql フォルダ** をドラッグ&ドロップ → Commit
3. `.github/workflows/collect.yml` を開く → 右上の鉛筆マーク → 中身を全部消して、zip の中の同じファイルの中身を貼る → Commit changes
4. Actions → collect → Run workflow → slot に `fill` → 緑の Run workflow で1回試す(25分)

- DB容量が増え続けないこと(/crawl のメーター、または実行結果の「DB容量」)
